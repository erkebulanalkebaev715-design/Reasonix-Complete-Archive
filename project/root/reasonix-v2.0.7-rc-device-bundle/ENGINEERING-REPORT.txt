REASONIX MOBILE v2.0.7 RC — ENGINEERING REPORT
Date: 2026-08-19

ROOT_CAUSES_FOUND:
1. AI breaker v2.0.6 used elapsed time (>45s) OR grouped action count >=5 as hard-stop signals. It did not model meaningful progress and could false-positive on legitimate long work.
2. Plus Tools/Plugins/Skills parsed backend responses with the wrong `.items` field. Backend contracts actually expose `.servers` and `.skills`, so visible lists could be empty/dead despite backend data.
3. Rounds/Verification were prompt-text injection, not actual Reasonix runtime capabilities.
4. Project state was mostly localStorage metadata/prompt injection and lacked a backend-persisted project container.
5. Voice input had no real Android native speech bridge in the safe v2.0.2-host lineage. Browser Web Speech is not a reliable implementation for this APK.
6. Backend diagnostics could not prove whether the CURRENT phone Reasonix tree actually contains evidence-aware core progress guard/reasoning source seams.

INVARIANTS_ADDED:
- Mobile emergency breaker never stops merely because 45 seconds elapsed.
- Permission/approval waiting is not treated as a loop.
- 1-2 duplicate calls are not a breaker condition.
- Generic repeated identical tool-result failure requires 5 repeats before mobile hard-break.
- Strong tool_not_found/schema/invalid-argument failures stop blind retry after 2 identical failures.
- Main no-progress strategy belongs to Reasonix core progress guard; APK breaker is secondary emergency protection.
- Plus visible Tools/Plugins/Skills read their real backend response shapes and mutate real backend state.
- Rounds/Verification map to backend-managed Reasonix Skills, not prompt injection.
- Projects persist server-side with id/name/workspace/sources/files/chatIds.
- Voice must be native Android SpeechRecognizer; no Web Speech fake fallback is treated as implemented.
- Native voice has bounded ~35s watchdog and terminal cleanup paths.
- No manual/handwritten DEX release path.
